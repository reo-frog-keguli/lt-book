# 無駄を生まないAI活用法 — LT資料

机の上の一冊の本をめくりながら進む、ライトニングトーク用のWebスライドです。
パワポ風の画面からカメラが引き、本が開き、見開きごとに水槽・星図・設計図・積み木の城などの世界に切り替わります。

**公開ページ**：https://reo-frog-keguli.github.io/lt-book/

## 見られる環境

- **PCの Chrome 157 以降**（HTML-in-Canvas を使っています）。それ以外のブラウザでは案内だけが表示されます
- 初回は3Dモデル（約43MB）の読み込みに少し時間がかかります

## 操作

| 操作 | 動き |
|---|---|
| Space / → / Enter / PageDown | 次へ（演出中にもう一度押すと最後まで飛ばす） |
| R | 最初から |
| マウス移動 | 本を見る角度を変える |
| Shift を押しながらマウス移動 | カメラを止めたまま、カーソルの効果だけを動かす |
| ホイール | 寄る・引く（`0` キーで戻す） |
| クリック | 設計図の部品を押す・便箋をつかむ |

`?step=番号` を付けて開くと、その場面まで早送りします（例：`?step=10`）。

## 技術選定

### 全体の構成

| 層 | 採用したもの | 理由 |
|---|---|---|
| ビルド | **Vite 8**（素のJavaScript、UIフレームワークなし） | 画面はほぼ1枚のWebGLキャンバスで、状態を持つUI部品がない。Reactなどを挟む利点が少なく、開発サーバーの再読み込みが速いことを優先した |
| 3D描画 | **three.js 0.187** | 本・机・水面・星空などをシェーダーで自作する部分が大半なので、薄い描画ライブラリで十分。React Three Fiber は見送り |
| 文字の描画 | **HTML-in-Canvas**（Chrome 157+） | ページの文字を、普通のHTMLとCSSで組んだまま3Dの紙面に貼るため（詳しくは下） |
| 3Dモデル | **Meshy**（MCP経由で生成） | 鯉・蓮・ロボット・積み木の城などの小物を、テキストから生成した |
| 公開 | **GitHub Pages**（GitHub Actions で自動ビルド） | `main` にプッシュすると自動で公開される静的サイト |

### ライブラリ

| パッケージ | 用途 |
|---|---|
| `three` | 3D描画全般。WebGLRenderer、ShaderMaterial、影、レンダーターゲット |
| `three/addons/loaders/GLTFLoader` | Meshyで生成したGLBモデルの読み込み |
| `three/addons/geometries/RoundedBoxGeometry` | 本の表紙・留め帯・机の小物の角を丸める |
| `three/addons/environments/RoomEnvironment` | 金属（留め金・金の輪）や革の映り込みに使う環境光 |
| `@fontsource/shippori-mincho` | 本文の日本語明朝体（OFL） |
| `@fontsource/cormorant-garamond` | 欧文の見出し・ページ番号（OFL） |
| `@fontsource/zen-kurenaido` | 手紙の見開きの手書き風文字（OFL） |

アニメーション（トゥイーン）、ノイズ、ページのめくり、水面の波の計算、紙片の分割などは、追加のライブラリを使わずに自作しています（`src/util.js` ほか）。

### HTML-in-Canvas の活用

Chrome 157 から使える、HTML要素をそのままキャンバスに描ける仕組みです。この資料では次の3か所で使っています。

1. **紙面の文字**
   `<canvas content="drawable">` の中に、見開きごとの文字を普通のHTMLで並べています（`index.html` の `L_s3h` などの層）。起動時に `ctx.drawElementImage()` で1層ずつビットマップにして、three.js の `CanvasTexture` として紙面のシェーダーに渡します。
   文字組み・フォント・行間はCSSのまま書けて、紙の丸みやインクの滲み、星空の上で光る金文字などはシェーダー側で付けています。
2. **冒頭のパワポ風画面**
   アプリ画面風のDOMを、見えているキャンバスに自分自身で描かせています（`paint` イベント）。カメラが引いてノートPCが見えたときも、同じ絵をノートPCの画面のテクスチャとして使うので、見た目が変わりません。
3. **水面で暗号化される文字**
   「生成する」「自律的な実行」の文字は、HTML側で1文字ずつ入れ替えながら毎フレーム取り込み、水面のシェーダーで波紋に沿って歪ませています。

取り込み用のキャンバスは、画面の外に出すと描画されません。そのため、不透明なWebGLキャンバスの真下に重ねて置いています。

### Canvas UI について

検討しましたが、**採用していません**。Canvas UI は平面のDOMをキャンバスに描く用途には向いていますが、この資料のように、傾いたりめくれたりする3Dの紙面に文字を貼る使い方には合いませんでした。同じ目的は、上の HTML-in-Canvas と three.js のテクスチャで実現しています。

### 外部MCP / API

| 名前 | 使い方 |
|---|---|
| **Meshy MCP**（Meshy API） | Claude Code から MCP 経由で3Dモデルを生成。`text-to-3d`（`meshy-t2.5` のスマートトポロジー）で形を作り、`refine` で質感を付けた。錦鯉・蓮の花・睡蓮の葉・ロボット・積み木の城・巻物・電源プラグ・パズルピースの8体 |

ロボットは Meshy の自動骨格付けと動き（転ぶ・歩く・喜ぶ・指さす）も試しました。ただ、元の姿勢の関係で肩や胴が崩れたため、最終的には骨格を使わず、体まるごとを動かす表現にしています。

本・机・紙面・水面・星空・霧・設計図の線などは、すべてコードとシェーダーで描いています（本は Meshy でも生成しましたが、金の線画が滲むためコード製に切り替えました）。

### 制作に使ったツール

| ツール | 役割 |
|---|---|
| **Claude Code** | 実装の大半を対話しながら作成 |
| **CdesignLS**（自作のデザイン用 Claude Code プラグイン） | 演出の要件ヒアリング → 調査・技術選定 → 試作 → 組み込み → 検証、までを段階ごとに承認しながら進めるためのプラグイン。ヘッドレス／実ウィンドウのブラウザで各場面を撮影し、フレームレートを測る検証スクリプトも含む |

### 主な自作の表現

- **本のめくり**：1枚の紙を、のどを軸にしならせながらめくる。めくり終えたコマで次の見開きに差し替えるので、前のページが見えない
- **インクの滲み**：文字が紙に沈んだり滲み出たりする表現（紙面のシェーダー）
- **水槽**：高さマップの波のシミュレーション、屈折、底に揺れる光の網、鯉の引き波。めくるときは水槽をその場で写した絵をページに刷り、めくり終えてから本物が動き出す
- **星図**：浮かぶ星と、光の線で結ばれていく星座。次の見開きへは、光の筋で紙面が斬られ、紙片が宙に浮いて燃え落ちる
- **霧と設計図**：カーソルのレンズで霧が晴れ、ぼやけた文字が読める。設計図の部品はクリックで押せる
- **積み木の城**：生成モデルを部品ごとのブロックに分け、一度に置くと崩れて砂になり、下から積み上げると立つ
- **影**：右上からの光で、立体の影が紙の丸みに沿って左下へ落ちる
